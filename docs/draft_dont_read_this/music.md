@AGENTS.markdown

添加对多媒体的支持。

代码组织方面，Media Runtime 在 `lib/media` 下。（Runtime 在这个项目里代表 Process-level lifetime）这个负责把 yt-dlp 抽象出来，因为后期可能会接多个后端。

数据模型上:

- 服务器上下载了什么音乐与播放列表分开。也就是说，服务端可以随时清理下载的音乐。从某种意义来看，已下载的音乐是一种物化视图。
- 一个已下载的音乐有几种逻辑状态 playable, advanced-metadata, metadata, dead（这个状态机只是逻辑模型，SQL里面用这个不一定合适）。其中 playable 代表服务器上有能直接用的音源，advanced-metadata 指服务器还留着封面这种大 metadata，metadata 指只有基本信息，例如曲名、专辑、作者等。
- 服务器采用 ref counting 机制。如果 ref count = 0，dead 状态将合法。淘汰时可以考虑向这个状态转移。
- 已下载的音乐有几种索引：Source + ProviderId 用于防止搜索新音乐后重复下载；Id 是音乐出现在服务器上时生成的 unique ID。
- 与 Articles 不同，已下载的音乐本身是全局共享的（类似文件分享型网盘按文件 hash 去重，防止存两份）。
- 存在几种播放列表：匿名播放列表（播放队列），播放列表。匿名播放列表适合：用户随处将 Track 增加进播放队列，这种用户一切换走就销毁；播放列表则是用户创建的真实播放队列。他们在本质上是同构的。

用户体验上：

- 一个音乐只要有基本的 metadata，都可以立刻加入播放列表与播放队列，避免用户还要等曲子开始下载才能开播。下载在后台进行。
- 支持 track 的流式传输。yt-dlp 是可以处理流式下载的。
- 默认缓存听过的歌（使用 files/extents infrastructure）。可根据需求设置保留策略（playlist-level）。

传输协议上：

- cover/audio stream 用 HTTP 传。

你主要需要考虑的东西，包括但不限于以下方面：

- 怎么设计 lib/media 抽象。
- 怎么管理 yt-dlp 运行，是否需要限流。（可以从 lib/tomato 借鉴 cooldown 实现）
- 怎么设计合理的数据模型，根据 全局共享已下载音乐、音乐与高级metadata可以不存在、ref counting 等等。
- 怎么处理流式体验。
- 怎么设计服务端淘汰策略。我的想法是，播放一次以后会 touch 一次，更新 lastPlayedTime。然后淘汰一周没放的。
- 怎么设计客户端的 playlist update。可以考虑对 track 进行 ref counting，对服务端 playlist 做 revision。
- 怎么做客户端的淘汰策略，可参考现有的文章下载（text/bundle）、对话下载等体验。
- 用 MUI 做规范、美丽、实用的 UI。包括播放列表、搜索、正在播放栏、播放队列等。
- 增加一套服务端控制最高音量的功能，可社区管理员调整。需要利用 WebAudio 打造一套播放管线（避开 Chrome 70 不支持的功能）。
- 需要整理服务端存储文件的 infrastructure。（目前 db 备份，音乐存储，PDRB bundle，teach document，AI file store都是零零散散的，尽量不要参考现有的实现，他们都是 poorly implemented 的。我正是希望你能推翻这些糟糕的设计与代码）
- 需要考虑怎么把 pot server 与 yt-dlp 打进生产包，而且能在 windows/linux 下正常，无需在线装依赖也能运行。

要求

- 允许你自由设计，你需要细致评估以上方案，提出你的深刻洞见，思考最佳的设计模式。
- 改动不限制 scope。
- 请在重要入口处简要用注释说明流程，比较复杂的点可适度添加注释，注释使用英文。

先评估这套方案。

## 额外信息

### pot server

需要打包为 self-contained（无需 node）、Windows-compatible 的版本。
避免直接用做 npm 依赖（GPL-3.0）。

```sh
git clone --single-branch --branch 1.3.1 https://github.com/Brainicism/bgutil-ytdlp-pot-provider.git
cd bgutil-ytdlp-pot-provider/server/
npm ci
npx tsc

node build/main.js --port ${free port}

# 同时需要仿照 GH workflow 里那样提取 plugin
```

### yt-dlp invocation

使用 yt-dlp standalone 版本：
https://github.com/yt-dlp/yt-dlp/releases/download/2026.07.04/yt-dlp_win.zip

基础参数:

```sh
yt-dlp \
    --extractor-args "youtube:player_client=web_music;youtubepot-bgutilhttp:base_url=http://127.0.0.1:${port}" \
    --js-runtimes "node:${process.execPath}" \
    --plugin-dirs xxx
    # 带上前面拿到的 plugin；ejs standalone 版本自带
```
